PROJECT: gguf-xray (repo name gguf-xray). One-liner: "Paste a Hugging Face GGUF link. See exactly what fits your GPU — read from the real file, not guessed."
Core flow: user pastes a HF model URL (e.g. https://huggingface.co/bartowski/Llama-3.2-1B-Instruct-GGUF or a direct .../resolve/main/x.gguf URL). If a repo, list its .gguf files via https://huggingface.co/api/models/<id>/tree/main (CORS works) with sizes, user picks one (default Q4_K_M-like). Then fetch the GGUF header using HTTP Range requests against https://huggingface.co/<id>/resolve/main/<file> (fetch incrementally: start with 2MB, grow if the header/tensor-info section is larger; never download the whole file). HF resolve redirects to a CDN that supports Range+CORS.
Hard parts to implement in src/lib:
1. A complete GGUF v2/v3 parser (little-endian; metadata KV with all value types incl. nested arrays; tensor infos: name, dims, ggml type, offset), working over a growable byte buffer, throwing a typed NeedMoreBytes error so the loader can fetch more. Big arrays like tokenizer.ggml.tokens should be skipped efficiently (count only).
2. ggml type table (block size + bytes per block for F32,F16,BF16,Q4_0,Q4_1,Q5_0,Q5_1,Q8_0,Q2_K..Q8_K,IQ*,TQ*,MXFP4) to compute exact per-tensor byte sizes; breakdown by type and by layer (blk.N.*).
3. Architecture-aware memory model from metadata (<arch>.block_count, context_length, embedding_length, attention.head_count, head_count_kv (may be per-layer array), key_length/value_length, sliding_window, expert_count/expert_used_count, MLA kv_lora_rank for deepseek2). KV cache bytes for chosen context and KV type (f16, q8_0, q4_0). Compute buffer estimate (document the formula).
4. Offload planner: given VRAM GB (presets 8/12/16/24/32/48/80 + Apple unified memory toggle using 75%), context, KV type -> max -ngl layers that fit, whether fully fits, and a ready-to-copy llama.cpp command (llama-server -m file -ngl N -c ctx -fa on [-ctk/-ctv]) and the Ollama env equivalent.
UI: one input + "Inspect" button. Results: big verdict line ("Fits fully on 16 GB with 32k context" / "Offload 22 of 32 layers"), sliders for context and VRAM, a monochrome stacked bar (weights / KV / buffer / free), a compact tensor-type table, collapsible raw metadata. Show bytes actually downloaded ("Read 1.8 MB of 4.9 GB"). Include 3 example chips (a small Llama 3.2 1B, a Qwen, a Gemma GGUF from bartowski or unsloth repos — verify the repos exist via curl). Also accept a local .gguf file via file picker (read with Blob.slice, same parser).
Tests: build synthetic GGUF buffers in tests to check the parser (all value types, v2 vs v3, truncated buffers -> NeedMoreBytes), type size math, KV formulas against hand-computed values for Llama-3-8B (32 layers, 8 kv heads, 128 head dim: 128 KiB per token f16), and planner.
